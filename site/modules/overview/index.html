    Module Overview

    The HTAN2 data model is organized into modular components that can be used independently or together. Modules are categorized into Record-Based and File-Based modules.

    Architecture

    graph TD
    A[HTAN2 Data Model] --> B[Record-Based]
    A --> C[File-Based]
    B --> D[Clinical]
    B --> E[Biospecimen]
    C --> F[CoreFile]
    F --> G[Sequencing Modules]
    F --> H[Imaging Modules]
    F --> I[Single-Cell & Spatial]
    G --> J[WES]
    G --> K[Sequencing Base]
    H --> L[DigitalPathology]
    H --> M[MultiplexMicroscopy]
    H --> N[Imaging Base]
    I --> O[scRNA-seq]
    I --> P[SpatialOmics]

    Record-Based Modules

    Record-based modules represent clinical and biospecimen data as records with unique identifiers.

    Clinical Module

    • Purpose: Clinical and demographic data
    • Structure: Multiple domain files (demographics, diagnosis, therapy, etc.)
    • Key Features: Comprehensive validation rules and conditional requirements
    • Overview | Schema Reference

    Biospecimen Module

    • Purpose: Comprehensive biospecimen metadata and classification
    • Structure: 18 domain-specific enum files with medical classifications
    • Key Features: RFC-compliant with 39 core attributes, ICD-10/ICD-O-3 integration
    • Overview | Schema Reference

    File-Based Modules

    File-based modules represent data files organized in hierarchical levels (Level 1, 2, 3, etc.). All file-based modules inherit from the CoreFile module.

    Core File Module

    • Purpose: Universal attributes shared across all file-based modules
    • Key Features: Single primary key definition, HTAN identifier validation patterns
    • Overview | Schema Reference

    Sequencing Modules

    WES (Whole Exome Sequencing)

    • Purpose: Bulk Whole Exome Sequencing data
    • Structure: Three processing levels (Level 1: raw, Level 2: aligned/QC, Level 3: variants)
    • Overview | Schema Reference

    Sequencing Base

    • Purpose: Base sequencing attributes shared across all sequencing types
    • Key Features: Library layout enums, sequencing platform enums, workflow metadata
    • Overview | Schema Reference

    Imaging Modules

    Digital Pathology

    • Purpose: Whole-slide imaging (WSI) data from H&E and other tissue-based assays
    • Structure: Single data level (Level 2) with Bio-Formats/OpenSlide compatible formats
    • Overview | Schema Reference

    Multiplex Microscopy

    • Purpose: Multiplexed tissue imaging assays (CODEX, CyCIF, IMC, MIBI, etc.)
    • Structure: Three data levels (Level 2: imaging, Level 3: segmentation, Level 4: cell-by-feature)
    • Overview | Schema Reference

    Imaging Base

    • Purpose: Base imaging attributes shared across all imaging modules
    • Key Features: De-identification methods, imaging equipment, microscopy parameters
    • Overview | Schema Reference

    Single-Cell & Spatial Modules

    scRNA-seq

    • Purpose: Single-cell RNA sequencing data
    • Structure: Three data levels (Level 1, 2, 3/4) with h5ad format validation
    • Key Features: Single-cell isolation methods, workflow types, AnnData schema compliance
    • Overview | Schema Reference

    Spatial Omics

    • Purpose: Sequencing-based and sequence-hybridization spatial omics assays
    • Structure: Four data levels (Level 1: raw bundle, Level 3: processed bundle, Level 4: interoperable file, Panel: panel info)
    • Key Features: Platform flexibility, bundle-level metadata, panel information
    • Overview | Schema Reference

    Module Relationships

    Inheritance Hierarchy

    CoreFileAttributes (CoreFile)
├── BaseSequencingAttributes (Sequencing)
│   ├── BulkWESLevel1/2/3 (WES)
│   └── scRNALevel1/2/3_4 (scRNA-seq)
├── BaseImagingAttributes (Imaging)
│   ├── DigitalPathologyData (DigitalPathology)
│   └── MultiplexMicroscopyLevel2/3/4 (MultiplexMicroscopy)
└── SpatialLevel1/3/4 (SpatialOmics)

    Data Flow

    Participant → Biospecimen → Data Files (Level 1 → Level 2 → Level 3)
